# SEO measurement and monitoring

Use for Search Console, analytics, field performance, URL inspection, sitemap reporting, visibility baselines, release comparisons, or ongoing SEO regression checks.

## Access and source control

Confirm the site/property, date range, comparison period, timezone, filters, environment, and business events that affect interpretation. Use the least-privileged authorised data source. Never expose credentials or copy unrestricted private data into reports.

Offer choices before connecting an account, enabling an API, consuming paid credits, creating a recurring monitor, or storing a baseline. Explain requested permissions, expected data, retention, cost, and manual/public-data fallback.

## Baseline

Capture only useful signals: important URLs, status/indexing state, title/canonical/robots/schema output, sitemap status, search queries and landing pages where authorised, conversions, crawl errors, and Core Web Vitals. Record collection method, date, environment, and missing fields.

## Compare and diagnose

Distinguish intentional releases from regressions. Prioritise changes that affect discoverability, page purpose, user journeys, or measurement validity. Correlation in traffic or ranking data is not proof of cause; test plausible explanations against releases, seasonality, demand, tracking changes, and external search changes.

## Output and monitoring

Report observed change, evidence source, affected scope, confidence, impact, likely causes, owner, action, and verification threshold. For recurring monitoring, notify only on a meaningful threshold breach, completion, failure, or required user action. Do not publish fixes, submit indexing requests, alter analytics, or create automations without explicit approval.
